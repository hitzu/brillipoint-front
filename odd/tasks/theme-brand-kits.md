# theme-brand-kits (frontend)

## Objective
Render the layered, backend-resolved event theme (`GET /events/:token/theme`) — tokens, typed image slots, decorations, social CTA, copy — without merging layers in the frontend, and remove the hardcoded Brillipoint CTA and pink fallback palette.

## Problem / why
- Customizing one event meant editing a shared theme (`decorativeIcon` was a patch).
- The Brillipoint social CTA (headline, WhatsApp button, IG/TikTok/FB) is hardcoded in `SocialMediaCTA` / `RecoverPhotosCTA`, used by 11 consumers; corporate events must show the client's socials and copy must be DB-editable.
- The fallback palette is a hardcoded pink; it must be the neutral, versioned `system-default.json` shared with the backend.

## Source of truth
- Backend repo `bookandsign-api`, branch `feat/theme-brand-kits` (not merged/deployed; tested locally).
- Types: `bookandsign-api/src/events/theme/theme.types.ts`; default: `bookandsign-api/src/events/theme/system-default.json` (version `2026-09-27`).
- Engram handoff: project `bookandsign-api`, topic `handoff/frontend/theme-brand-kits` (#2358).

## Constraints
- Scope (user decision 2026-09-27): only the `/fiesta` (`FiestaPage`) and `/mis-fotos` (`MisFotosPage`) routes, which live in `src/features/party/`. The `/party/[token]` route (`PartyPublicPage`) is deprecated: do not modify it or components used exclusively by it. `/inspiracion` (`InspirationPublicPage`) is IN scope (user decision 2026-09-27).
- Frontend never merges layers; `socialCta: null` → hide block, no fallback.
- `images` is typed slots `{path,url,alt?:{es,en},link?}` (replaces flat `Record<string,string>` / `splashEmblem`).
- Event without preset → 200 with `id: null`, `key: "system-default"`.
- Respect ETag/304; no client cache longer than 5 min.
- UI chrome strings stay as frontend i18n.
